# Upgrading from v0.5.0 to v1.0.0

v1.0.0 ("versioned & interactive") is the first stable release. Updates now come from release tags only, the
daily brief starts with a checklist of decisions you can tick, you can type commands such as `tailor <url>` in
Claude Code, and each run is saved in a local history of your workspace. Your CV, letters and settings don't
change, but **your workspace folder becomes a git repository**, and the title filter keeps a few more student
titles.

Older engine? Go to [v0.5.0](v0.5.0.md) first; "update the engine" does both steps in one go, but read both
guides for what changes.

## Before you start
- Your scheduled task must still be a local Code-tab task in permission mode Auto (see [v0.3.0](v0.3.0.md)).
- Close any running scheduled run (the update changes `.claude/`).
- git must be installed (it already is if "update the engine" worked before).
- About 10 minutes. Nothing is sent anywhere: the new history stays on your computer.

## How to update
Open the workspace folder in Claude Desktop's **Code** tab and say:

```text
update the engine
```

Claude follows [UPGRADING.md](../../UPGRADING.md). What is new for v1.0.0:

| Step | Command Claude runs | What it means for v1.0.0 |
|---|---|---|
| 1 Fetch | `git -C engine fetch --tags origin` | The new engine is the newest release tag (`v1.0.0`), not the tip of `main`. |
| 2 Look | `python engine-new/tools/upgrade.py status` | `engine: 0.5.0`, `channel: stable` and `update: release v1.0.0`. |
| 4 Update | `python engine-new/tools/upgrade.py apply` | engine/ is now on the tag `v1.0.0`, not on a branch. That is expected. |
| 5 Settings | `python engine/tools/upgrade.py migrate` | config.yaml stays at version 2 and gets `engine_channel: stable`. It copies the four command skills (`tailor`, `why`, `sent`, `job-status`) into `.claude/skills/` and the updated tailor subagent. |
| 6 Check | `python engine/tools/setup_check.py --init` | **The v1.0.0 step.** It makes the workspace folder a local git repository with a `.gitignore` (unless it is one already) and must say READY. A warning "the workspace is inside another repo" means a folder above it is a git repo: the daily runs then aren't saved; move the workspace or ignore the warning. |
| 7 Prove | `upgrade.py compare` | Expect **SAME DOCUMENTS**. The titles part lists ledger titles the new title filter treats differently (below). |

Then click **Run now** on the scheduled task once and check the brief (below).

## What changes in the daily run
- **The brief starts with a version line:** `engine 1.0.0 (commit) · model <id>`. Each job.md has an
  `- **Engine:**` line, and new ledger rows name the engine and model.
- **Decisions checklist.** Below the version line, a "Decisions" list: tailor a job that scored 60-69, mark
  today's drafts as sent, skip a draft that is 7-14 days old. Tick a box (`[x]`) in the brief file and the next run
  does it and lists it under "Done from your decisions". Unticked boxes stay for 7 days. Weekend runs keep a ticked
  "tailor" for Monday.
- **Workspace history.** Each run ends with a commit like "daily run 2026-11-03, engine v1.0.0". It has no remote
  and is never pushed. To see what a run changed, ask Claude "what did the last run change?"; to undo it, ask
  Claude to revert that commit. `engine/` and `backups/` aren't in the history.
- **Commands.** In Claude Code you can say `tailor <url>` (one job, with the daily run's checks), `why <job>`
  (the score explained), `sent <folder>` (tracker row, folder to `_sent/`) and `status` or `/job-status` (your
  pipeline at a glance).
- **Title filter.** `manager`, `staff`, `leiter` and `lead` now drop only Junior and unlabelled titles, so a
  title such as "Werkstudent Produktmanagement" is now kept and scored. Every other exclude word matches at the
  start of a word only: `art` no longer drops "Startup Marketing". Expect a few more student jobs in the brief.
- **Update check.** The brief says "engine update available" only when a newer release is out, not for every
  commit on GitHub.

## Check that it worked
After the first **Run now**:
1. The brief's first line is `engine 1.0.0 (...) · model ...`.
2. The brief has a "Decisions" section (it can be empty on a quiet day).
3. `git log -1` in the workspace folder shows "daily run <today>, engine v1.0.0". If the run's reply (Run now shows it) says the history
   commit failed, show Claude the message; a global `commit.gpgsign=true` in your git settings is a known cause.

## Going back
`python engine/tools/upgrade.py rollback` puts the old engine and config.yaml back. The workspace history
(`.git/` and `.gitignore`) stays: v0.5.0 ignores it. Delete the `.git` folder only if you don't want the history.
The new skills in `.claude/skills/` stay and do nothing with v0.5.0.
