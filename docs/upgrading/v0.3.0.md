# Upgrading from v0.2.0 to v0.3.0

v0.3.0 ("safe & lossless") puts limits on the unattended daily run that hold even if a job ad tries to talk the
agent into something: permission rules and a guard hook. It also stops the search and the seen-jobs ledger from
losing jobs, and gives the engine a version number. Your CV, letter and config.yaml settings don't change.

Older engine? Go to [v0.2.0](v0.2.0.md) first; "update the engine" does both steps in one go, but read both
guides for what changes.

## Before you start
- **Your scheduled task must be a Code-tab task that runs only on this computer, in permission mode Auto.** The
  new safety rules live in your workspace's `.claude/` folder, and only a local Code-tab task reads them. A
  cloud or Cowork task runs without them (see [the spike](../spike-scheduled-tasks.md)). Check it in Claude
  Desktop: Code tab > Scheduled > your task > Advanced settings > General > **Only on this computer** on;
  permission mode **Auto**. [SETUP.md](../../SETUP.md) step 3 shows where.
- Close any running scheduled run (the update rewrites `.claude/settings.json`).
- About 10 minutes. Nothing is sent anywhere; the comparison builds test documents locally.

## How to update
Open the workspace folder (the one with `engine/` and `config.yaml`) in Claude Desktop's **Code** tab and say:

```text
update the engine
```

v0.2.0 already knows this command; Claude follows the steps in [UPGRADING.md](../../UPGRADING.md). What you'll
see, step by step:

| Step | Command Claude runs | What it means for v0.3.0 |
|---|---|---|
| 1 Fetch | `git -C engine worktree add ../engine-new origin/main` | The new engine sits next to the old one in `engine-new/`. |
| 2 Look | `python engine-new/tools/upgrade.py status` | Now shows version numbers: `engine: no VERSION` (v0.2.0 has no VERSION file) and `engine version on GitHub: 0.3.0`. |
| 3 Back up | `upgrade.py prepare` | `backups/pre-upgrade-<date>/` gets config.yaml, CLAUDE.md, custom.md, cv/ and a patch of any edits inside engine/. Claude asks "Update now?" |
| 4 Update | `upgrade.py apply` | Pulls v0.3.0 into `engine/`. |
| 5 Settings | `python engine/tools/upgrade.py migrate` | **The v0.3.0 step.** config.yaml stays at version 2 (no key changes). It adds the permission rules and the guard hook to `.claude/settings.json` and copies `.claude/hooks/jobhunt_guard.py`. Rules and hooks you already have stay; `settings.local.json` isn't touched. Expect "permission rules: added N to .claude/settings.json" and the list. |
| 6 Check | `python engine/tools/setup_check.py --init` | Must say READY. New lines: the engine version on the first line, "safety: permission rules" ok, and "guard hook starts and blocks" ok (it starts the hook once to prove it blocks). |
| 7 Prove | `upgrade.py compare` | Builds a test application and up to 5 of your real ones with both engines. v0.3.0 doesn't change the document builder, so expect **SAME DOCUMENTS** and the same result for every ledger title. |
| 8 Offers | | Wishes in custom.md that v0.3.0 covers get marked; nothing new to set up. |
| 9 Finish | `upgrade.py finish`, after your yes | Removes `engine-new/`, the test builds and the saved old engine. The backup stays. |

Then click **Run now** on the scheduled task once and check the brief (below).

### If `.claude/settings.json` isn't valid JSON
Step 5 then prints "permission rules: NOT INSTALLED" with the error. Claude shows it to you, fixes the file with
your OK, and runs `python engine/tools/setup_check.py --init`, which installs the rules.

## What changes in the daily run
These are the CHANGELOG's behaviour changes, in practice:

- **The brief's Sources section gets two lines:** the engine version (`engine 0.3.0 (a1b2c3d)`) and
  `guard active: N call(s) checked, M blocked this session`. If it ever says **guard NOT active**, the run had no
  guard: the line is repeated under "Your actions". Check the task's settings (local Code task, Auto).
- **Some tool calls are refused.** The run can no longer send, reply, forward or draft email, trash or spam-mark
  mail, type into web pages or fill forms, share Drive files, or change `engine/`, `.claude/` or your master CV
  and letter. Those calls end with "denied by your permission settings" or a guard reason. Nothing the routine
  does needs them: it still reads Gmail, drafts follow-ups as files and tailors copies of your CV.
- **curl and WebFetch only reach the job APIs and the hosts in companies.md and sources.md.** Other web pages
  are read with the browser. A host you add to companies.md or sources.md is allowed from the next call on.
- **Links the browser opens can't carry your data.** Your name, email, phone, address or birth date in a link is
  refused, also when it's encoded (base64, hex). On a site that isn't in companies.md or sources.md, any
  encoded or random-looking value is refused too; the run opens the page without it (a LinkedIn job page works
  without its tracking values).
- **Everything stopped is listed** under **Blocked by the guard**, with what the run did instead: `blocked`
  lines for the guard, `refused` lines for calls the permission rules refused.
- **More jobs can show up, once.** The ledger now counts a job as already seen only when the company matches and
  the title has the same words (any order, gender forms and punctuation ignored). Jobs the old check wrongly
  hid ("SAP CO" behind "SAP FI", "Senior" behind "Junior") appear as new the first time. Reposts with
  reordered words or the other gender form now count as seen.
- **Broad Arbeitsagentur searches find more.** Each search reads up to 3 pages of 100 results instead of only
  the first 100. If a search has even more, the brief names it ("page limit") and suggests a narrower term or
  radius.
- **An ad text that can't be fetched no longer loses the search.** The run tries again or opens the job page,
  and the brief says which ads couldn't be read.
- The job sources see the engine as `jobhunt-agent/0.3.0` instead of a browser.

## Check that it worked
After the first **Run now**:
1. The brief's Sources section shows `engine 0.3.0 (...)` and `guard active: ... 0 blocked` (or a "Blocked by
   the guard" list that makes sense).
2. `python engine/tools/hooks/guard.py --status` in the workspace prints `guard active` while a run is going,
   and `data/guard.json` has today's time.
3. No `refused` or `blocked` line in the brief is for a step the routine needs (searching, reading ads,
   writing applications). If one is, say so in an issue: a rule is too strict.

## Going back
`python engine/tools/upgrade.py rollback` puts the old engine and config.yaml back. The permission rules and the
hook stay in `.claude/settings.json` and do no harm with v0.2.0 (the hook file calls the engine's guard; if it
isn't there, the hook lets everything through and `setup_check.py` doesn't check it). To remove them too, copy
`.claude/settings.json` back from before the update: it's in your workspace's git history if you commit it.
