# Upgrading from v1.0.0 to v1.1.0

v1.1.0 ("your own design") lets the builder keep more of your master CV: its own fonts, a tailored tagline in the
letter, and more projects than fit on two pages. It also adds phrases a CV or letter must never contain. Every
new setting is optional: **without them your documents stay exactly the same**, and config.yaml stays at
version 2.

Older engine? Go to [v1.0.0](v1.0.0.md) first; "update the engine" does both steps in one go, but read both
guides for what changes.

## Before you start
- Close any running scheduled run (the update changes `.claude/agents/tailor.md`).
- About 10 minutes. Nothing is sent anywhere.

## How to update
Open the workspace folder in Claude Desktop's **Code** tab and say:

```text
update the engine
```

Claude follows [UPGRADING.md](../../UPGRADING.md). What is new for v1.1.0:

| Step | Command Claude runs | What it means for v1.1.0 |
|---|---|---|
| 2 Look | `python engine-new/tools/upgrade.py status` | `engine: 1.0.0`, `update: release v1.1.0`. |
| 5 Settings | `python engine/tools/upgrade.py migrate` | config.yaml stays at version 2. It updates the tailor subagent (it orders a project pool). |
| 7 Prove | `upgrade.py compare` | Expect **SAME DOCUMENTS**: nothing changes until you set one of the new settings. |

## The new settings (all optional)
- **Your own fonts:** `font: keep` in config.yaml keeps the master CV's and letter's fonts, so a two-font design
  (a text font and a mono font for headings) survives tailoring and the PDF page check stays on.
  `fallback_font` can name a substitute per font: `{Inter: Arial, JetBrains Mono: Consolas}`.
- **Never write:** `never_write: ["3 products", 'stopped deploying\s+by hand']` lists phrases or regexes that must
  never appear in a CV or letter, for example a fact your CLAUDE.md forbids. A match fails the build, so the tailor
  fixes the letter.
- **Numbers as words:** the grounding check also reads "three" or "zwölf". One that isn't in your files or the ad
  is a warning; `grounding_number_words: fail` makes it an error.
- **Letter tagline:** map `letter: headline:` in cv/layout.yaml and the builder fills it from `letter_headline:` in
  each application.md (one text or `{de: ..., en: ...}`), else from the CV headline. Say "remap my CV" to map it.
- **Project pool:** give a section in cv/layout.yaml `max: N` and `further: {starts_with: "..."}`: each CV shows the
  first N projects in the job's order as full blocks and names the others on the "further projects" line. Your
  master can then hold more projects than fit on two pages.

Also fixed: one stale cv/variants.yaml entry (its master text no longer in the CV) no longer stops every build,
only the builds that use it; `cv_map.py check` lists stale entries.

## Check that it worked
After the first **Run now**, the brief's first line is `engine 1.1.0 (...) · model ...`. If you set one of the new
settings, open one tailored CV and letter from that run and check the fonts, the tagline or the projects line.

## Going back
`python engine/tools/upgrade.py rollback` puts the old engine and config.yaml back, so settings you added after
the update are gone with it; v1.0.0 doesn't know them.
