# Upgrading from v0.3.0 to v0.4.0

v0.4.0 ("measurable judgment") changes how the daily run reads and scores jobs. A separate ad reader with no
write or send tools reads every ad, so the run never sees raw ad text, and fit scores come from a written rubric
instead of a number the model picks. Your CV, letters and config.yaml settings don't change.

Older engine? Go to [v0.3.0](v0.3.0.md) first; "update the engine" does both steps in one go, but read both
guides for what changes.

## Before you start
- Your scheduled task must still be a local Code-tab task in permission mode Auto (see [v0.3.0](v0.3.0.md)).
- Close any running scheduled run (the update changes `.claude/`).
- About 10 minutes. Nothing is sent anywhere.

## How to update
Open the workspace folder in Claude Desktop's **Code** tab and say:

```text
update the engine
```

Claude follows [UPGRADING.md](../../UPGRADING.md). What is new for v0.4.0:

| Step | Command Claude runs | What it means for v0.4.0 |
|---|---|---|
| 2 Look | `python engine-new/tools/upgrade.py status` | `engine 0.3.0` and `engine version on GitHub: 0.4.0`. |
| 5 Settings | `python engine/tools/upgrade.py migrate` | **The v0.4.0 step.** config.yaml stays at version 2. It copies `.claude/agents/ad-reader.md` into the workspace (the ad reader). If `.claude/settings.json` denies the `Agent` tool, it saves the file as `.claude/settings.json.bak-<date>` and removes that rule (`removed deny Agent`): the run needs it to call the reader. |
| 6 Check | `python engine/tools/setup_check.py --init` | Must say READY. It warns while `ad-reader.md` is missing or `Agent` is still denied. |
| 7 Prove | `upgrade.py compare` | v0.4.0 doesn't change the document builder: expect **SAME DOCUMENTS**. |

Then click **Run now** on the scheduled task once and check the brief (below).

## What changes in the daily run
- **Ads are read by the ad reader.** The run hands each new job to the `ad-reader` subagent, which fetches the
  ad (job API text, Indeed, Gmail alerts, the browser) and returns only fixed facts as JSON: role type, German
  level, hours, requirements, whether the ad is closed. The extracts are saved in `data/ads/`, and each job
  folder gets `ad.json` and `ad.txt`. Each ad costs one extra model call, about $0.05.
- **Scores come from the rubric** (`engine/rubric.md`): five sub-scores from 0 to 5 (skills, seniority, language,
  location, hours) and `score.py` computes the total. Scores can move by several points against older briefs,
  and a hard mismatch (for example a city you can't reach) always lands below 60. config.yaml `scoring:` changes
  the weights.
- **Ads the reader couldn't read come back.** A blocked or empty page is listed as "couldn't be read" and tried
  again in the next run. A page that is gone (404, 410) counts as closed.
- **Old jobs come back after 90 days.** A job screened, skipped or closed more than 90 days ago shows up as new
  when it's still online or reposted. config.yaml `ledger_expiry_days` changes the days (0 = never).

## Check that it worked
After the first **Run now**:
1. The brief's Sources section shows `engine 0.4.0 (...)` and `guard active: ...`.
2. `data/ads/` has a `.json` file for each new job, and each tailored job's job.md lists its five sub-scores.
3. Jobs the brief lists as "couldn't be read" aren't in `data/seen_jobs.csv`.

## Going back
`python engine/tools/upgrade.py rollback` puts the old engine and config.yaml back. `.claude/agents/ad-reader.md`
stays and does nothing with v0.3.0. To restore a removed `Agent` deny rule, copy
`.claude/settings.json.bak-<date>` back to `.claude/settings.json`.
