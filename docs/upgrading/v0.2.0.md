# Upgrading from v0.1.0 to v0.2.0

v0.2.0 ("smoother updates, German letters") is the release that brought "update the engine": a backup, a
comparison of old and new documents, and a rollback. It also adds German cover letters and a few optional
settings. Nothing changes for a workspace that doesn't use the new settings.

After this, continue with [v0.3.0](v0.3.0.md) (one more "update the engine"; a single update from v0.1.0 lands
on the newest release and does both).

## Before you start
- v0.1.0 doesn't know "update the engine" yet. This first update uses a prompt you paste (below); every later
  one is just "update the engine".
- Workspaces from **before v0.1.0** (the engine that only knew IT job titles and one fixed two-column CV) take
  the same route. The v0.2.0 update writes the `profile:` block and `cv/layout.yaml` for you (see "Workspaces
  from before v0.1.0" below), so you don't need the long manual prompt that v0.1.0's UPGRADING.md had.
- About 10 to 15 minutes. Close any running scheduled run.

## How to update
Open the workspace folder (the one with `engine/` and `config.yaml`) in Claude Desktop's **Code** tab and paste:

```text
Update my job-hunt engine safely. Work in this folder (it contains engine/ and config.yaml). First check that you
can run commands here (git --version, python --version); if you can't, stop and tell me to open this folder in
Claude Code's Code tab. Then run `git -C engine fetch origin`, read the update instructions with
`git -C engine show origin/main:UPGRADING.md`, and follow its "Steps for Claude". Don't commit, push or delete
anything without asking me.
```

Claude reads the update steps from the new engine on GitHub, so the old engine doesn't need to know them. The
steps run the **new** engine's `upgrade.py` from `engine-new/`. What you'll see:

| Step | Command Claude runs | What it means for v0.2.0 |
|---|---|---|
| 1 Fetch | `git -C engine worktree add ../engine-new origin/main` | The new engine sits next to the old one in `engine-new/` (and in `.gitignore`). |
| 2 Look | `python engine-new/tools/upgrade.py status` | The commits since your engine, any local edits inside `engine/`, and `config version: 1` (v0.1.0 files have no `config_version` key yet). |
| 3 Back up | `upgrade.py prepare` | `backups/pre-upgrade-<date>/` gets config.yaml, CLAUDE.md, cv/, a copy of the old engine and a patch of any edits you or Claude made inside `engine/`. For each edit Claude names the new setting that does the same job, or drafts a wish for `custom.md`. Then it asks "Update now?" |
| 4 Update | `upgrade.py apply` | Your edits are set aside with `git stash` (kept in the backup too) and v0.2.0 is pulled into `engine/`. |
| 5 Settings | `python engine/tools/upgrade.py migrate` | Your `profile:` and `cv/layout.yaml` stay as they are. It adds `config_version: 2`, and, if they're missing, `internship_duration: 12 months` and `pdf_engine: word` (what the old engine assumed). Keys the new engine doesn't read are listed, never deleted. Then it checks the CV map. |
| 6 Check | `python engine/tools/setup_check.py --init` | Must say READY. |
| 7 Prove | `upgrade.py compare` | Builds a test application and up to 5 of your real ones with both engines and compares them part by part, plus the title filter on every title in your ledger. |
| 8 Offers | | A narrower `profile:` if CLAUDE.md describes a narrower search, and a check of `custom.md` wishes against the CHANGELOG. Each only on your yes. |
| 9 Finish | `upgrade.py finish`, after your yes | Removes `engine-new/`, the test builds and the saved old engine. The backup stays. |

### What the comparison should say
**SAME DOCUMENTS** is the normal result. Two v0.2.0 changes can show up as a difference in the cover letter,
and Claude explains which one it is:
- `letter.recipient` now replaces the whole address block (several lines), not one paragraph. If your letter's
  address has several lines, the new letters have the full new address instead of a mix of old and new lines.
- `letter.closing`, if you map it, ends the body at the closing line even without an empty line before it.

Anything else is a real difference: Claude stops and offers `upgrade.py rollback`.

## What's new to use
All optional; set them in config.yaml or cv/layout.yaml, or ask Claude to.

| Setting | What it does |
|---|---|
| `letter_languages: [de]` or `[de, en]` (config.yaml), `languages:` (application.md) | One letter per language. German letters get German checks ("ab sofort", "Stunden pro Woche", phrases to avoid). |
| `name_in_master` (config.yaml) | Your name as the master files spell it (e.g. with a middle name); documents say `applicant` instead. |
| `search.areas` (config.yaml) | Search these places instead of a nationwide pass. |
| `search.regions`, `region_plz`, `region_places` (config.yaml) | Keep only jobs in these federal states (e.g. Bayern), by region, postcode start or place name. |
| `cv.date` (cv/layout.yaml) | A "City, DD.MM.YYYY" line on the CV follows the letter date. |
| `not_list` item rule, list-valued `name_split` (cv/layout.yaml) | For CV projects whose bullets are Word list items, and for item names split at more than one character. |
| `custom.md` (workspace) | A wish list for things the engine can't do yet. Every later update checks it against the CHANGELOG. |

From now on the daily brief says "engine update available: say 'update the engine'" when GitHub has a newer
engine, and `setup_check.py` warns when something edited files inside `engine/` (that blocks clean updates;
wishes belong in custom.md).

## Workspaces from before v0.1.0
Same prompt. In step 5 `migrate` also:
- writes a `profile:` block. From `search.keep_titles` / `drop_titles` if you had them, otherwise the old built-in
  IT filter, copied exactly. Step 7 proves every ledger title gets the same result; step 8 offers to narrow it
  to your field.
- writes `cv/layout.yaml` from `cv_layout` / `letter_layout`, or from the old fixed two-column table, and drops
  those keys. If your CV isn't laid out the way the old engine expected, it stops with "couldn't map the CV
  automatically": say **remap my CV** and Claude builds the map with you.
- turns `internship_months` into `internship_duration`.

## Going back
`python engine/tools/upgrade.py rollback` (or `python engine-new/tools/upgrade.py rollback` if step 4 hasn't
finished) brings back the old engine, its local edits and the old config.yaml; a cv/layout.yaml the update wrote
is moved into the backup folder. By hand: `git -C engine reset --hard <old commit>` (the commit is in
`backups/pre-upgrade-<date>/upgrade.json`), `git -C engine stash pop` if edits were set aside, and copy
config.yaml back from the backup.
